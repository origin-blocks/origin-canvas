== Description ==

Canvas is a free block theme for solo developers, freelancers and small teams who build client sites in the Block Editor.

Every pattern uses the theme's colors, type and spacing, so sections line up from page to page. Templates, patterns and styles are in place from the first page.

Choose from 12 style variations, which restyle every pattern at once. Change any part of the site in the Site Editor.

== Installation ==

1. Log in to your WordPress site and go to **Appearance > Themes > Add New > Upload Theme**.
2. Click **Choose File** and select the theme's ZIP file on your computer. Click **Install Now**.
3. Click **Activate**.

== Upgrading from 1.3.1 ==

This version gives the theme's colors, one spacing size and one line-height value new names. Classes and variables take the new names too, so `has-text-muted-color` becomes `has-contrast-3-color` and `--wp--preset--color--text-muted` becomes `--wp--preset--color--contrast-3`. Primary keeps its name.

= New Names =

Colors:

* `surface-base` is now `base`
* `surface-muted` is now `base-2`
* `on-dark` is now `base-2`
* `surface-subtle` is now `base-3`
* `surface-subtle-hover` is now `base-4`
* `border` is now `base-5`
* `input-border` is now `base-6`
* `text-muted` is now `contrast-3`
* `text-body` is now `contrast-2`
* `text-heading` is now `contrast`

Spacing:

* `compact` is now `small-medium`

Line height:

* `body` is now `normal`

= Sites Updated in Place =

On a site updated in place, compatibility styles keep the renamed colors, spacing and line height rendering the same, except in the five cases and the known limits below. The theme loads those styles only on sites that ran it before this version, on the front end, in the Block Editor and in the Site Editor. Saved content keeps the old names. This version's design changes are separate from the rename, and the changelog lists them.

In the default palette, body and muted text are also one step darker in this version, separately from the rename: `contrast-3` is #4B5563 where `text-muted` was #6B7280, and `contrast-2` is #374151 where `text-body` was #4B5563. Field and Outline button borders are darker too, also separately from the rename: a field border is #828B98 where it was #D1D5DB, and an Outline button border is #6B7280 where it was #E5E7EB. Fields now read Contrast 5 and Outline buttons read Contrast 4, so a site that set Input Border or Border in Styles no longer sees those colors on fields and Outline buttons.

Five cases render differently:

* CSS in a child theme or in Additional CSS that targets an old class name doesn't reach newly inserted blocks, which carry the new class, so list the new class as its own selector beside the old one, as in `.has-surface-muted-background-color, .has-base-2-background-color`.
* Additional CSS that overrides an old variable at `:root`, such as `--wp--preset--color--text-heading`, still recolors saved content on that name but no longer reaches the theme's own styling, which reads the new name. Add a declaration for the new name beside the old one, since saved content still reads the old one.
* On a site using the theme's palette, text set to the old Border color loses that color, because its class, `has-border-color`, is also the class WordPress adds to any block with a border color, so clear the text color in the editor and choose Base 5. A site whose saved palette still lists Border isn't affected.
* A custom color saved under a slug the theme now uses, such as `base` or `contrast`, overrides the theme's color of that name, so rename the custom color in Styles, which gives it a new slug, and choose it again on the blocks that used it.
* On a site whose saved Styles replaced the palette, the theme's dark bands and dark menus use Base 2 for their text where 1.3.1 used On Dark, and the theme takes Base 2 from Surface Muted. If a style variation or a user set Surface Muted and On Dark to different colors, as Editorial, Expressive and Refined Sans do in 1.3.1, the bands and menus show the Surface Muted color. Content set to On Dark keeps its color. The bands' background was fixed at #111827 in 1.3.1 and now follows Contrast, so a saved palette or style variation with another Text Heading color shows that color on the bands, such as #1C1917 in Editorial.

= Known Limits =

The theme treats a site as new when it activates on this version, and as updated when this version loads with no activation. That leaves four known limits:

* A site that ran 1.3.1, switched to another theme, or from this theme to its child, and comes back after this update counts as new, so it loads no compatibility styles.
* A site activated on 1.3.1 with no page load before this update also counts as new, so content with old names imported during that activation doesn't get compatibility styles. The same goes for a site that activates this version and then imports a 1.3.1 export.
* A site whose theme is set without an activation counts as updated and loads compatibility styles it never uses.
* A site updated in place whose first load after this update is a Customizer preview of the active theme shows that one preview without compatibility styles. The next page load outside the preview adds them.

One more limit sits in the Site Editor: on a site whose saved Styles hold the old palette, choosing a style variation changes the palette at once while the compatibility styles stay as they loaded, so a block saved on an old name can show no color in the canvas until you reload the editor; the front end isn't affected.

A tool that moves saved content to the new names is available on request from support.

== Changelog ==

= 1.3.1 - 1 September 2026 =
* Lightened the default heading weight and handed heading weight to the style variations. Headings in your content set lighter than before, as do the pattern headings that were heavier than the default — the landing hero and closing call to action drop furthest, having been heavier still. Switching style variation reaches headings inside patterns, which previously kept their own weight. A few deliberate exceptions keep theirs: the large statement sections, the site title and the comment reply heading.
* Put every pattern heading on the type scale, replacing hand-written sizes so the fluid curve and every style variation reach them, and settled the text-led sections on one shared reading width.
* Enlarged the icons across the theme to a single size, so the drawn mark matches the design instead of floating undersized in its disc.
* Widened the tracking on the section eyebrows and seated each one with the heading it introduces.
* Refined the style-variations and token-system showcase patterns: specimens sit on a shared baseline, group headers sit with the cards they label, and the status chips carry their size on the block where the editor's size control can reach it.
* Fixed the icon bubbles rendering as ovals, and collapsing when their background color was removed.
* Fixed the feature cards centering their icons above left-aligned text, evened out the rule spacing in the feature list with image, and gave the same client the same role in both testimonials.
* Fixed the landing hero asking for a weight heavier than the bundled fonts provide, which the browser had been faking.

= 1.3.0 - 7 August 2026 =
* Added patterns for text sections, FAQs, teams, pricing, features and testimonials, taking the library to 61.
* Added a "Minimal" style for the Accordion block — flat hairline rows and a fine open/close mark instead of the default card treatment. Apply it from the block's Styles panel; an Accordion you have not styled is unchanged.
* Stepped the heading ladder so h1-h6 read as distinct levels in your content, reducing h2 to 36px and h3 to 30px from their previous larger sizes. Headings inside patterns are pinned to their own sizes and are unaffected.
* Rebuilt the sidebar as four sections behind the theme's eyebrow treatment — search, recent posts, categories and tags — held by a single hairline, with the category list capped and ordered by post count.
* Closed the single post with an author card carrying the avatar, name and bio, and settled the spacing between the article, the card and the comments.
* Added a single-post template with a sidebar.
* Replaced six pattern categories that duplicated ones WordPress already provides, so Text and Testimonials no longer appear twice in the inserter.
* Reworked pattern keywords across the library, so searches for terms like headshot, masthead or endorsement reach the right pattern.
* Fixed the testimonial avatar in the feature split, which rendered as an oval when its row was squeezed.
* Retired the redundant Display font preset, which was identical to Sans and made the editor's font control tick both entries. Existing content keeps rendering Inter.

= 1.2.0 - 9 July 2026 =
* Switched the default button fill to solid dark (ink) and made pink an opt-in 'Fill Primary' style. Existing plain buttons will appear dark after updating — reapply Fill Primary to restore pink.
* Promoted the primary button to pink on the dark hero and dark call-to-action banner, where the ink fill would be invisible.
* Completed the primary-as-accent color model: moved body/comment links, pagination current page, comment and search submit buttons, form focus rings, and tag-chip hover to ink/neutral tones, reserving pink for hovers and deliberate accents. Fixes tag-chip and badge contrast (AA).
* Added an "Author" pill badge on comments written by the post author — ink text on a faint primary tint that follows your color style variation. Developers can disable it via the new origin_canvas_render_author_badge filter.
* Added support for the editor's sticky Position setting on the site header — when enabled, the whole header sticks and submenus layer correctly above page content.
* Reworked mobile navigation: tap-to-expand inline accordion submenus, Lucide chevron icons on desktop and mobile, and aligned close/expand controls.
* Fixed nested list spacing compounding: scoped list rhythm to post content with margin-top-only gaps, so deeply nested items no longer over-space; pattern/chrome lists use tight default spacing.
* Refined single-post typography: two-tier byline (ink author, muted date), category lead rendered as an uppercase eyebrow, and section eyebrows raised to 600 weight.
* Added the Hero Canvas landing hero and renamed the Studio page pattern.
* Cleaned up unused legacy post-grid styles left over from a superseded pattern; removed a duplicate Text pattern category; de-underlined post-loop dates and titles.

= 1.1.0 - 17 June 2026 =
* Redesigned the single-post comments as quiet bubble cards with clearer thread rhythm, nested-reply indentation, and a tidier reply form.
* Added a name-led author card to single posts, with the avatar and name balanced in lockstep.
* Added a Stacked variation for post navigation (previous/next), with an eyebrow label and refined single-post spacing.
* Added Chip and Inline style variations for post tags and the tag cloud, selectable and recolorable in the editor.

* Added token-driven outline buttons (including an on-dark variant for the dark hero) and refined button hover states.
* Loaded per-block stylesheets into the block editor canvas so the editor preview matches the front end.
* Various comment, sidebar, and link color refinements, plus consistent alphabetical CSS property ordering.
* Switched the homepage to a user-owned front page: the Home design is now an insertable pattern you place into a Page and set as your static front page, so you fully own and can edit its content (removed the theme-locked front-page template).
* Wired the site header as a single global template part, so editing the header once updates it across every template — matching how the footer already worked.
