Pick one of 12 style variations and every pattern in Origin Canvas changes with it: colors, type or both. The theme is free and ships 100 patterns in 18 categories, 12 templates and 7 full-page layouts: two home pages, about, services, pricing, contact and a landing page. Every pattern is built from core blocks and uses the theme's presets, so sections line up from page to page, and you edit it all in the Site Editor with no page builder or other plugin. Pages stay ordinary WordPress blocks, so whoever runs the site can keep editing them. See it live in your browser, with nothing to install: https://playground.wordpress.net/?theme=origin-canvas

== Description ==

Canvas is a free block theme for solo developers, freelancers and small teams who build client sites in the Block Editor.

Every pattern uses the theme's colors, type and spacing, so sections line up from page to page. Templates, patterns and styles are in place from the first page.

Choose from 12 style variations, which restyle every pattern at once. Change any part of the site in the Site Editor.

== Installation ==

1. Log in to your WordPress site and go to **Appearance > Themes > Add New > Upload Theme**.
2. Click **Choose File** and select the theme's ZIP file on your computer. Click **Install Now**.
3. Click **Activate**.

== Upgrading from 1.3.1 ==

This version gives the theme's colors, one spacing size and one line-height value new names. Classes and variables take the new names too, so `has-text-muted-color` becomes `has-contrast-3-color` and `--wp--preset--color--text-muted` becomes `--wp--preset--color--contrast-3`. Primary keeps its name.

= New Names =

Colors:

* `surface-base` is now `base`
* `surface-muted` is now `base-2`
* `on-dark` is now `base-2`
* `surface-subtle` is now `base-3`
* `surface-subtle-hover` is now `base-4`
* `border` is now `base-5`
* `input-border` is now `base-6`
* `text-muted` is now `contrast-3`
* `text-body` is now `contrast-2`
* `text-heading` is now `contrast`

Spacing:

* `compact` is now `small-medium`

Line height:

* `body` is now `normal`

= Sites Updated in Place =

On a site updated in place, compatibility styles keep the renamed colors, spacing and line height rendering the same, except in the five cases and the known limits below. The theme loads those styles only on sites that ran it before this version, on the front end, in the Block Editor and in the Site Editor. Saved content keeps the old names. This version's design changes are separate from the rename, and the changelog lists them.

In the default palette, body and muted text are also one step darker in this version, separately from the rename: `contrast-3` is #4B5563 where `text-muted` was #6B7280, and `contrast-2` is #374151 where `text-body` was #4B5563. Field and Outline button borders are darker too, also separately from the rename: a field border is #828B98 where it was #D1D5DB, and an Outline button border is #6B7280 where it was #E5E7EB. Fields now read Contrast 5 and Outline buttons read Contrast 4, so a site that set Input Border or Border in Styles no longer sees those colors on fields and Outline buttons.

Five cases render differently:

* CSS in a child theme or in Additional CSS that targets an old class name doesn't reach newly inserted blocks, which carry the new class, so list the new class as its own selector beside the old one, as in `.has-surface-muted-background-color, .has-base-2-background-color`.
* Additional CSS that overrides an old variable at `:root`, such as `--wp--preset--color--text-heading`, still recolors saved content on that name but no longer reaches the theme's own styling, which reads the new name. Add a declaration for the new name beside the old one, since saved content still reads the old one.
* On a site using the theme's palette, text set to the old Border color loses that color, because its class, `has-border-color`, is also the class WordPress adds to any block with a border color, so clear the text color in the editor and choose Base 5. A site whose saved palette still lists Border isn't affected.
* A custom color saved under a slug the theme now uses, such as `base` or `contrast`, overrides the theme's color of that name, so rename the custom color in Styles, which gives it a new slug, and choose it again on the blocks that used it.
* On a site whose saved Styles replaced the palette, the theme's dark bands and dark menus use Base 2 for their text where 1.3.1 used On Dark, and the theme takes Base 2 from Surface Muted. If a style variation or a user set Surface Muted and On Dark to different colors, as Editorial, Expressive and Refined Sans do in 1.3.1, the bands and menus show the Surface Muted color. Content set to On Dark keeps its color. The bands' background was fixed at #111827 in 1.3.1 and now follows Contrast, so a saved palette or style variation with another Text Heading color shows that color on the bands, such as #1C1917 in Editorial.

= Known Limits =

The theme treats a site as new when it activates on this version, and as updated when this version loads with no activation. That leaves four known limits:

* A site that ran 1.3.1, switched to another theme, or from this theme to its child, and comes back after this update counts as new, so it loads no compatibility styles.
* A site activated on 1.3.1 with no page load before this update also counts as new, so content with old names imported during that activation doesn't get compatibility styles. The same goes for a site that activates this version and then imports a 1.3.1 export.
* A site whose theme is set without an activation counts as updated and loads compatibility styles it never uses.
* A site updated in place whose first load after this update is a Customizer preview of the active theme shows that one preview without compatibility styles. The next page load outside the preview adds them.

One more limit sits in the Site Editor: on a site whose saved Styles hold the old palette, choosing a style variation changes the palette at once while the compatibility styles stay as they loaded, so a block saved on an old name can show no color in the canvas until you reload the editor; the front end isn't affected.

A tool that moves saved content to the new names is available on request from support.
